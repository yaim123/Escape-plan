# 열쇠공방 · 교육용 방탈출 제작 플랫폼

명세서 `SPEC.md`를 기준으로 만든 **1차 개발 버전**입니다. 사용자의 선택에 따라 로컬 체험을 먼저 구현했습니다. 전체 v1 수업 운영 기능의 완성본은 아닙니다.

## 바로 실행

Node.js 22 이상에서 프로젝트 폴더를 열고 실행합니다. 외부 패키지 설치가 필요 없습니다.

```powershell
node scripts/serve.mjs
```

브라우저에서 http://127.0.0.1:4173 을 여세요. `index.html`을 더블 클릭하는 `file://` 실행은 ES 모듈을 불러오지 못하므로 지원하지 않습니다.

1. **예제 살펴보기**를 누르면 수정 가능한 과학 방탈출 예제가 생성됩니다.
2. 왼쪽 블록을 선택해 이야기, 문제, 정답, 힌트 등을 수정합니다.
3. **플레이 테스트**에서 실제 입력과 힌트, 탈출 결과를 확인합니다.
4. **내 방탈출**로 돌아가 복제하거나 JSON 파일로 백업합니다.

## 현재 작동하는 기능

- 방탈출 생성, 수정, 복제, 삭제, 목록 검색 및 개인전/팀전 필터
- 콘텐츠 자동 저장 및 수동 저장, 저장 실패 표시, 저장 실패 시 이동 방지
- 스토리·문제·안내·조건 대기 블록과 고유 ID
- 블록 복제·삭제, PC 드래그 순서 변경, 키보드·터치용 위/아래 이동 버튼
- 단답·숫자·객관식·복수 선택·OX·순서·짝맞추기·암호·스위치·조건 달성·교사 승인 등 11개 유형의 제작 및 테스트
- 복수 정답, 공백·대소문자·특수문자 정규화 설정
- 이미지·영상·음성 URL, YouTube 임베드
- 학생 미리보기와 전체화면 스토리 미리보기
- AND·OR·N개 이상 공개 조건, 팀원 번호·역할·이벤트 필터
- 가상 팀의 문제 배정과 완료 판정, 참가자 시점 변경, 교사 승인 시뮬레이션
- 개인/팀/스테이지 힌트 제한, 단계별 힌트, 시간 페널티, 오답 횟수
- 처음부터/현재 블록부터 테스트, 테스트 도착 시각·점수·소요 시간
- 같은 탭 새로고침 시 테스트 복구, 테스트 초기화와 콘텐츠 원본 분리
- 버전·참조·순환 조건·미디어 URL 검증을 포함한 JSON 가져오기/내보내기
- Supabase 연결 설정, 교사 이메일 로그인/가입, 개인 소유 콘텐츠 CRUD 연결 코드와 RLS SQL
- 회원가입 없는 학생 입장, 같은 브라우저 복구, 실시간 명단·팀 선택·정원 제한, 교사의 게임 시작
- 실제 학생 문제/스토리 플레이, 서버 정답 판정, 오답 횟수와 진행 저장, 팀 완료 공유 및 교사 진행도

Supabase 프로젝트의 공개 연결과 네 테이블의 익명 접근 차단을 실제 서버에서 확인했습니다. 교사 권한의 읽기·쓰기 검사는 로그인 후 **저장 공간 설정 → 연결·읽기·쓰기 검사**에서 실행합니다. 최신 실행 결과와 검증 범위는 `docs/SUPABASE_CONNECTION.md`를 확인하세요.

실제 학생 대기실은 `supabase/002_live_lobby.sql` 적용 후 **콘텐츠 목록 → 대기실 → 대기실 열기**로 사용합니다. 학생용 주소는 `#/join`이며 방 코드가 포함된 `#/join/123456` 링크도 지원합니다. 설치·보안 구조·실제 검증 결과는 [대기실 문서](docs/LIVE_LOBBY.md)에 기록했습니다. 실제 문제 플레이는 `supabase/003_live_play.sql` 적용 후 새 대기실에서 사용할 수 있습니다. 서버 정답 판정·진행 저장·팀 실시간 공유·교사 진행도까지 구현했습니다. [플레이 구현 및 검증 기록](docs/LIVE_PLAY.md)을 확인하세요. 교사 제어 기능은 `004_teacher_controls.sql`과 보완 `005_teacher_team_event_fix.sql` 적용 후 사용합니다. [교사 제어 문서](docs/TEACHER_CONTROLS.md)를 참고하세요. 결과·점수·힌트·순위·종료·초기화는 `006_results_and_reset.sql` 적용 후 사용할 수 있습니다. [결과 및 초기화 검증 기록](docs/RESULTS_AND_RESET.md)을 참고하세요. QR 상호작용은 후속 범위입니다.

## 저장 위치와 주의점

- 콘텐츠: 이 사이트 주소에 연결된 브라우저 `localStorage`
- 테스트: 해당 탭의 `sessionStorage`에 별도 저장. 입력한 오답 문자열은 기록하지 않음
- 온라인 모드: Supabase `escape_contents`에 교사 소유 문서 저장
- 로컬 데이터와 온라인 데이터는 자동 병합하지 않음. JSON 내보내기/불러오기로 이동
- 테스트는 교사 전용입니다. 정답이 교사 브라우저에 있으므로 실제 학생에게 테스트 URL을 배포하면 안 됩니다.
- 브라우저 데이터 삭제 시 로컬 콘텐츠가 사라질 수 있습니다. JSON 백업을 사용하세요.
- 콘텐츠를 수정해 저장하면 해당 콘텐츠의 이전 테스트 진행은 새로 시작합니다.
- 로컬 타이머는 기기 시각을 사용하며, 실제 학생 수업의 서버 타이머를 대신하지 않습니다.

## Supabase를 나중에 연결하기

이 프로젝트는 Next.js가 아닌 정적 HTML/CSS/JavaScript입니다. `NEXT_PUBLIC_…` 또는 `.env`를 브라우저에서 자동으로 읽지 않습니다.

- 배포 기본 설정: `src/config.js`의 `SUPABASE_CONFIG.url`, `SUPABASE_CONFIG.key`
- 초기화: `src/app.js` → `getConfig()` → `new SupabaseRepository(config)`
- 통신: 기존 `src/data/supabase.js`의 REST 클라이언트 사용. 별도 SDK/CDN 설치 없이 Auth 및 PostgREST에 연결
- 현재 브라우저만 다른 프로젝트로 연결: **저장 공간 설정**에서 변경. 이 값은 기본 설정보다 우선
- 기본값으로 복원: **배포 기본 설정 사용** 버튼
- 배포: 빌드가 공개 설정을 검증하고 `dist/src/config.js`에 포함. 기존 GitHub Pages workflow를 그대로 사용

설정 파일에는 Project URL과 공개용 Publishable Key만 넣습니다. 로그인 후의 사용자 토큰은 프로젝트 URL별로 분리된 탭 저장소에 보관하며 빌드 파일에 포함하지 않습니다. 브라우저 설정을 다른 프로젝트로 바꿔도 이전 프로젝트의 토큰을 보내지 않습니다.

제공된 프로젝트의 공개 기본값은 이미 반영되어 있습니다. 새 프로젝트로 변경할 때는 다음 순서를 따르세요.

1. 새 Supabase 프로젝트를 만듭니다.
2. SQL Editor에서 `supabase/001_foundation.sql`을 **한 번** 실행합니다.
3. Auth의 이메일/비밀번호 인증과 이메일 인증 설정을 확인합니다.
4. Auth URL 설정의 Site URL / Redirect URLs에 실제 배포 주소를 등록합니다.
5. 공통 배포 설정은 `src/config.js`, 현재 브라우저만의 설정은 앱의 **저장 공간 설정**에서 프로젝트 URL과 공개키를 입력합니다.
6. 교사 로그인 또는 가입을 진행합니다. 이메일 확인이 켜져 있으면 메일 인증 후 로그인합니다.
7. **저장 공간 설정 → 연결·읽기·쓰기 검사**에서 테스트 콘텐츠 생성·조회·수정·삭제와 권한 차단을 검증합니다. 검사 중 만든 ID만 정리하며 기존 콘텐츠는 수정하지 않습니다.
8. 실제 학생 대기실은 `supabase/002_live_lobby.sql`, 실제 문제 플레이는 `supabase/003_live_play.sql`을 순서대로 한 번 실행합니다. 교사 제어는 이어서 004·005, 결과·초기화는 006을 적용합니다. 이미 적용한 프로젝트에서는 다시 실행하지 않습니다.

학생에게는 콘텐츠 테이블 접근 권한을 부여하지 않습니다. 브라우저에 service_role/secret 키를 넣지 마세요. 학생 API는 정답을 서버에서 검증하고, 본인에게 공개된 표시용 콘텐츠만 반환합니다.

공식 문서: [Supabase 비밀번호 인증](https://supabase.com/docs/guides/auth/passwords), [Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security).

## 검증 및 정적 배포 준비

```powershell
node --test
node scripts/build.mjs
```

공개 연결과 익명 접근 차단만 터미널에서 검사하려면 `node scripts/check-supabase.mjs`를 실행하세요. 이 명령은 로그인 정보 없이 실행하며, 교사 읽기·쓰기 항목은 `대기`로 보고합니다. GitHub Actions에는 실서버 검사를 추가하지 않았습니다.

`dist/`에 HTML/CSS/JavaScript만 복사합니다. SQL, 테스트, 명세서, 로컬 설정 파일은 배포 파일에 포함하지 않습니다. Google Fonts가 연결되지 않으면 시스템 글꼴을 사용합니다.

GitHub 저장소가 준비되면 소스를 올리고 Settings → Pages에서 GitHub Actions를 선택합니다. Actions의 **Publish GitHub Pages**를 수동 실행하면 됩니다. 경로는 상대 경로이고 화면 전환은 해시 라우팅을 사용하므로 저장소 하위 경로에서도 작동합니다. 이 작업에서는 GitHub 저장소 생성 또는 외부 배포를 하지 않았습니다.

## 코드 구조

```text
src/core/       콘텐츠 모델, 정답 판정, 조건 엔진, 가상 세션 로직
src/data/       로컬 저장소, Supabase 어댑터, 예제 콘텐츠
src/ui/         목록, 제작기, 플레이어, 인증/설정 화면
src/app.js      화면 전환과 저장소 선택
src/styles.css 반응형 스타일
supabase/      교사 콘텐츠 권한과 후속 수업 데이터 기반
tests/         정답·조건·세션·저장소 테스트
scripts/       로컬 서버, 정적 배포 빌드
docs/          구현 현황과 후속 개발 설계
```

남은 작업과 설계 제한은 `docs/IMPLEMENTATION.md`에 정리했습니다.
