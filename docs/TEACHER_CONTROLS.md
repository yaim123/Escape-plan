# 교사 실시간 게임 제어

## 설치

기존 001~003 이후 `supabase/004_teacher_controls.sql`을 한 번 실행합니다. 팀 이동 후 같은 문제 재풀이의 이력 충돌을 방지하는 `supabase/005_teacher_team_event_fix.sql`도 이어서 한 번 실행합니다. 이미 적용한 파일은 다시 실행하지 않습니다. 기존 001~003은 변경하지 않았으며, 004 적용 이후 발견한 수정도 004를 고치지 않고 005로 분리했습니다.

004·005 모두 사용자가 현재 Supabase에 적용했고 실서버 검증까지 완료했습니다. 추가 SQL 실행은 필요하지 않습니다.

## 화면과 적용 범위

교사 대기실에서 게임을 시작하면 실시간 진행 화면에 전체 일시정지 / 게임 재개가 표시됩니다. 학생 이름을 누르면 **해당 학생만**, 조 관리 버튼을 누르면 **해당 팀 전체** 패널을 엽니다. 패널은 적용 대상을 명시하고 확인 체크 후 실행합니다. 패널을 연 뒤 진행이 바뀌면 서버가 오래된 요청을 거절하므로 최신 상태로 패널을 다시 열어야 합니다.

- **강제 완료 / 건너뛰기**: 선택한 학생들의 각 현재 콘텐츠를 통과 처리합니다. 정답을 제출하거나 정상 풀이 기록을 위조하지 않습니다. 두 동작은 조건 재평가를 위해 완료로 취급하지만 관리 기록에서 구분합니다. 팀원별 현재 콘텐츠가 다르면 각각의 현재 콘텐츠에 적용합니다. 대상 중 현재 콘텐츠가 없으면 전체 요청을 거절합니다.
- **개별 적용**: 개인별 예외 기록을 통해 그 학생만 통과합니다. 다른 학생의 일반 팀 완료 판정을 바로 바꾸지 않습니다. 이후 정상 학생 풀이 이벤트는 기존 팀 공유 규칙대로 적용됩니다.
- **팀 전체 적용**: 선택 시점 팀원 모두에게 예외를 적용하고 팀 완료·공개 조건을 재평가합니다. 개인별 예외가 생긴 팀의 요약 진행률은 팀원 진행률의 평균입니다.
- **콘텐츠 이동 / 스테이지 이동**: 지정한 콘텐츠 또는 해당 스테이지의 첫 콘텐츠를 열고 현재 위치를 옮깁니다. 배정과 공개 조건을 넘어 이동할 수 있으며 다른 선행 콘텐츠를 모두 완료 처리하지 않습니다. 이미 완료한 콘텐츠도 다시 열어 볼 수 있습니다.
- **잠금 해제**: 지정 콘텐츠를 선택 가능한 목록에 추가합니다. 현재 콘텐츠가 유효하면 현재 위치는 유지합니다. 성공적으로 완료하면 임시 열림 예외를 제거합니다. 오답만으로 예외를 제거하지 않습니다.
- **선택 대상 진행 초기화**: 선택한 참가자의 이벤트·오답·완료·중복 제출 영수증·강제 예외를 지웁니다. 팀 공유 과거 완료로 즉시 건너뛰지 않도록 초기화 시점 이후 이벤트부터 다시 평가합니다. 다른 학생들의 공유 조건도 재평가하므로 기존 팀 완료 판정이 달라질 수 있습니다. 이름·참가 토큰·팀·수업·원본 콘텐츠·교사 조작 이력은 유지합니다. 수업 전체 초기화 기능은 아닙니다.
- **팀 변경**: 시작 후에도 교사가 선택 학생 또는 팀원들을 지정 조로 옮길 수 있습니다. 정원을 우회하지 않습니다. 기존 팀원 번호는 재배열하지 않고 새 번호를 발급합니다. 정상 풀이 이벤트의 당시 팀·팀원 번호·역할은 보존하므로 과거 풀이를 새 팀 풀이로 바꾸지 않습니다. 개인 예외는 학생을 따라가고, 이전 팀 전체 예외는 새 팀에 적용하지 않습니다. 이동 후 현재 위치는 새 팀 조건에 맞춰 다시 선택합니다.

관리 작업은 playing 또는 paused 수업에서만 실행할 수 있습니다. 학생 조작은 playing에서만 실행 가능합니다. 일시정지 중 교사가 위치를 조정한 경우에는 재개 후 조정된 위치가 표시됩니다.

## 일시정지와 시간

일시정지 시 학생 화면을 전체 화면 대기 UI로 바꿉니다. 새로고침·재접속도 서버 상태를 읽어 대기 UI로 돌아갑니다. 서버 정답 제출과 콘텐츠 선택은 paused 상태에서 거부되고, 학생의 팀 변경·정보 변경·퇴장도 시작 후 기존 제한을 유지합니다. 접속 유지용 touch와 읽기는 허용합니다. 실제 힌트 API는 아직 없으며 지원하지 않는 동작은 RPC가 거절합니다.

세션의 `paused_at`, 누적 `paused_ms`를 서버에서 기록합니다. 유효 시간은 서버 시작 시각부터 현재/정지/종료 시각까지의 시간에서 누적 일시정지를 뺀 값입니다. 중복 일시정지 요청으로 시작 시각을 다시 설정하지 않습니다. 정지 상태에서 수업을 종료해도 그 구간을 제외합니다.

각 참가자의 `completed_elapsed_ms`는 모든 콘텐츠 완료 시 유효 시간을 저장합니다. 이 값은 재접속해도 고정되며, 교사 조작으로 미완료 상태가 되면 다시 계산할 수 있도록 비웁니다. 진행 초기화나 팀 이동은 수업 시작 시각 자체를 바꾸지 않습니다. 순위·최종 결과 화면은 만들지 않았습니다.

## 테이블과 권한

| 대상 | 변경 |
| --- | --- |
| `escape_sessions` | 정지 시작 시각, 누적 정지 밀리초 |
| `escape_participants` | 진행 초기화 기준 시각, 완료 유효 시간 |
| `escape_events` | 이벤트 발생 당시 팀/팀원 번호/역할. 005에서 당시 소속까지 포함한 중복 방지 인덱스 |
| `escape_progress_overrides` | 참가자·블록별 교사 완료/건너뛰기/해제 예외와 적용 범위 |
| `escape_teacher_actions` | 교사 ID·요청 UUID·작업·대상 UUID·이전 위치/팀·목표 콘텐츠/스테이지/팀·서버 시각 |

새 테이블의 RLS를 활성화하고 anon/authenticated 직접 접근을 차단합니다. 원본 콘텐츠 RLS 및 학생 정답 비노출을 유지합니다. `escape_teacher_control`은 authenticated만 호출 가능하고 내부에서 auth.uid와 세션 소유자를 확인합니다. 세션 행 잠금으로 제출·일시정지·관리 요청을 직렬화하고, revision으로 오래된 관리 요청을 차단하며 request UUID로 네트워크 재시도를 중복 처리하지 않습니다.

실제 오답 문자열은 여전히 저장하지 않습니다. 학생 정상 완료는 `escape_events.source=student`, 승인형 문제 승인은 teacher로 기록하며, 강제 조작은 별도 관리 테이블에 남습니다. 진행 초기화로 관리 이력이 사라지지 않습니다. 관리 이력과 예외는 학생 응답에 포함하지 않습니다. 학생에게는 허용된 현재 콘텐츠와 진행 상태만 반환하고, paused일 때는 현재 콘텐츠도 반환하지 않습니다. Realtime은 기존과 같이 빈 변경 신호만 보냅니다.

## 최종 실서버 확인 및 정리 (2026-09-24)

005 적용 후 B가 정상 완료 이력을 가진 상태로 2조→1조→2조 이동하며 같은 스토리를 재완료했습니다. 복귀 시 팀원 번호는 기존 이벤트와 충돌하지 않는 3번으로 부여됐고 단답·객관식·암호도 서버 정답 판정으로 정상 완료했습니다. 교사 대시보드에 모든 참가자 4/4와 완료 유효 시간이 표시됐습니다. A의 완료 시간은 이후 팀 변경과 재접속에도 1분 3초로 유지됐습니다. 관리 이력 12건에서 강제 완료·건너뛰기·스테이지·해제·이동·초기화·팀 변경·정지·재개가 각각 구분됐습니다. 최종 정상 플레이 콘솔 오류/경고는 세 탭 모두 0건입니다.

폐기용 콘텐츠 `c420a89c-128a-4d7e-a7c4-d805d2bfda77` (코드 568650)를 소유 교사로 삭제했습니다. Supabase 콘텐츠 목록 재조회 0건, 기존 학생 A/B 및 API 참가자의 토큰으로 참가 기록 조회 불가를 확인했습니다. 세션·참가·완료·제출·교사 조작·강제 예외 테이블은 ON DELETE CASCADE로 연결되어 함께 삭제됩니다. 이 연쇄 삭제는 로컬 SQL 검사에서도 확인했습니다. 관리자 권한으로 모든 테이블의 전역 COUNT를 조회한 것은 아니며 소유자 목록·토큰 거부·외래키 제약을 근거로 확인했습니다. 교사 Auth 계정은 유지했습니다.
