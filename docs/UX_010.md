# 010 — 인증, 대기실 제작본, 자료 경고, 몰입형 스토리

## 적용 순서

1. Supabase SQL Editor에서 `supabase/010_lobby_assets_and_immersive.sql` 전체를 새 쿼리로 한 번 실행한다. 001~009는 수정/재실행하지 않는다.
2. Auth > URL Configuration 값을 아래와 같이 확인한다.
3. 변경 코드를 GitHub Pages에 배포한다. 신규 대기실 UI는 010 RPC가 필요하므로 SQL을 먼저 적용한다.

이 작업에서는 실제 Supabase 데이터 변경, 배포, 이메일 발송을 수행하지 않았다.

## Auth 설정

Site URL:

```text
https://yaim123.github.io/Escape-plan/
```

Redirect URLs에 다음을 등록한다 (이미 있는 항목은 중복 등록하지 않음):

```text
https://yaim123.github.io/Escape-plan/
https://yaim123.github.io/Escape-plan/?auth=confirm
http://127.0.0.1:4173/
http://127.0.0.1:4173/?auth=confirm
```

로컬 링크는 로컬 서버가 실행 중일 때만 열린다. 이메일 템플릿의 기본 `{{ .ConfirmationURL }}` 링크를 사용한다. 이 프로젝트의 REST signup은 implicit flow이며 PKCE challenge를 만들지 않는다. `redirect_to`는 hash가 없는 현재 사이트 경로와 `?auth=confirm`을 전달한다. 콜백은 앱 라우터보다 먼저 해석하고 URL에서 토큰을 즉시 제거한다. 토큰으로 `/auth/v1/user`의 이메일 인증 여부를 확인하며 콜백 토큰을 브라우저 저장소에 저장하지 않는다. 확인 뒤 사용자가 로그인하므로 기존 로그인/로컬 콘텐츠 가져오기 흐름은 유지된다. 만료·재사용·지원하지 않는 query-code 링크는 인증 성공이라고 단정하지 않는다.

공식 동작 참고: [Implicit flow](https://supabase.com/docs/guides/auth/sessions/implicit-flow), [Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls).

## 데이터/보안 변경

- `escape_sessions.snapshot_source_hash`: 제작 원본 JSON의 버전 지문. 자료 제거 후에도 동일 제작본으로 판정한다.
- `escape_sessions.assets_acknowledged`: 해당 snapshot에 대한 자료 경고 확인 여부. 기존 세션은 기본 false.
- 새 교사 전용 RPC `escape_lobby_snapshot`: inspect / open / refresh / assets. `auth.uid()`와 콘텐츠 소유권을 검사한다. 기존 RLS/익명 권한은 확대하지 않는다.
- 제작본 행 → 세션 행 순서로 잠금. 갱신은 같은 lobby 세션, 같은 제작본 및 snapshot 지문일 때만 허용한다. playing/paused/finished, 오래된 확인창, 다른 교사/익명 호출은 거부한다.
- 참가자와 팀을 유지할 수 없는 개인/팀 방식 변경, 팀 수 축소 또는 정원 축소는 거부한다. start_play가 기존 서버 방식으로 역할/조건/진행을 초기 계산한다.
- 실행 검증은 구조·정답·참조·QR·순환 오류를 차단한다. 배경/첨부 URL은 경고이며 동의 후 **snapshot만** 정리한다. 원본과 보관 결과를 변경하지 않는다.
- 유효한 외부 이미지/음성/영상은 시작 전에 최대 4초씩, 동시 8개로 로드 확인한다. 실패한 URL은 확인창에 표시하고 동의 시 snapshot에서 제외한다. YouTube iframe은 교차 출처 로드 성공을 신뢰성 있게 확인할 수 없어 사전 검사에서 제외한다. 런타임 실패도 진행을 막지 않는다.
- `public_block`은 새 공개 필드 `immersiveOverlay`만 추가한다. 정답/RPC 판정/QR capability/결과·초기화 트랜잭션은 기존 구조를 사용한다.

## UI와 호환성

- 사본 만들기는 기존 duplicateRoom을 사용하며 `(사본)`, 새 방 코드와 블록/QR 식별자로 독립한다.
- 제작기: 대기실 열기 / 진행 상황. 교사 대기실·진행 화면: 방탈출 편집. 이동은 수업을 종료/초기화하지 않는다.
- 수정된 lobby 제작본 반영은 선택 사항. 기존 내용 유지 시 쓰기 없음.
- 초기화 모달은 이번 수업 기록 삭제가 기본. 보관은 직접 선택하며 다른 과거 수업 기록은 유지한다.
- story만 `display: immersive`. `immersiveOverlay` 생략 시 true. card/theme/image 및 full→theme 변환 유지.
- 공통 몰입형 renderer: cover 이미지, 하단 body, 정보 버튼, 터치 안내. 실제 플레이는 100dvh, preview는 제한된 프레임. 정보/자막 스크롤/컨트롤은 진행 클릭과 분리한다. 이미지 영역 클릭과 Enter/Space는 기존 submit 경로를 사용한다.
- 이미지 실패 시 어두운 배경으로 자막/정보/진행 유지. overlay OFF는 정상 이미지에서 어두운 글자와 약한 흰 그림자, ON은 별도 검은 그라데이션과 흰 글자.

## 로컬 검증

```text
node --test
node scripts/verify-play-sql.mjs --controls --results --editor-flow --ux
node scripts/verify-controls-sql.mjs --results --editor-flow --ux
node scripts/verify-results-sql.mjs --editor-flow --ux
node scripts/verify-editor-flow-sql.mjs --ux
node scripts/verify-ux-sql.mjs
node scripts/verify-ux-ui.mjs
node scripts/build.mjs
```

Node 66개 테스트, PGlite SQL 5개 스위트, 독립 headless UI 시나리오, 빌드 통과. SQL 테스트는 로컬 DB에서 실제 함수를 실행하고 fixture 정리까지 확인한다. UI 테스트는 실계정 없이 임시 로컬 서버와 mocked RPC를 사용해 콜백 bootstrap, 버튼/기본값, preview/fullscreen, 정보 클릭 분리, 키보드 진행, 기존 서버 submit 호출을 검사한다. 실제 Supabase Realtime/이메일 전달 여부를 이번 테스트로 검증했다고 간주하지 않는다.

배포 후 사람이 확인할 항목: 새 가입 메일 성공/재사용 안내, 대기실↔편집 이동과 최신 내용 반영, 두 학생 중 진행 중/일시정지 snapshot 고정, 모바일 몰입형 이미지 crop/자막/터치, 자료 경고 후 시작 및 초기화 선택. 카메라 QR 재검증은 이번 변경에 필요하지 않다.
