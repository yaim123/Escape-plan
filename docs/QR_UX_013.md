# QR 저장·학년·스캔 확인 개선

2026-09-27. 구현과 로컬 검증 완료. 실제 Supabase 적용·배포는 수행하지 않음.

## 변경 내용

- 제작기의 개별 QR 저장은 **PNG 저장**이 기본, **SVG 저장**은 보조 버튼이다. PNG는 QR 모듈을 정수 픽셀로 직접 그려 최소 800×800px, 흰 배경·검은 무늬, 4모듈 quiet zone을 유지한다. Windows 파일명 금지 문자를 제거하고 `_QR.png` / `_QR.svg`로 저장한다. 저장은 기존 URL과 token을 사용하며 문서/DB를 변경하지 않는다.
- QR 일괄 인쇄는 기존 SVG·A4·크기·수량 설정을 그대로 사용한다.
- 공유 학년 목록에 고1·고2·고3을 추가했다. 전체 설정, 메인 필터, 카드 배지가 같은 문자열 metadata를 사용한다. 기존 중학교/미분류 콘텐츠를 다른 값으로 변환하지 않는다.
- QR 스캔 성공은 “QR을 찾았습니다!”와 확인 버튼으로 표시한다. ALL/N_OF_M/UNIQUE_MEMBER는 **방금 스캔한 미션**에 대한 서버 응답의 인정 개수/필요 개수를 표시한다. 최종 스캔으로 다음 블록이나 결과에 도달해도 이전 미션의 진행도를 잃지 않는다.
- 서버의 스캔·완료·조건 판정·실시간 알림은 즉시 처리한다. 스캔한 학생의 화면 전환만 확인까지 기다린다. 확인 중 들어온 실시간 응답은 가장 최신 revision을 보관했다가 적용한다. 교사의 일시정지/종료/초기화는 확인 대기보다 우선한다.
- 미완료 미션은 확인 후 계속 스캔할 수 있다. 성공/실패 모달 표시 중에는 카메라 해독과 링크/이미지 제출을 차단한다. 확인 후에도 카메라에 그대로 남은 동일 QR을 연속 전송하지 않는다. 다음 QR이나 빈 화면을 비추면 재인식할 수 있다.
- 실패의 구체적인 서버 메시지와 기존 UNIQUE_MEMBER 판정은 유지한다. 이미 처리된 QR은 새 성공으로 표시하지 않는다. 확인 버튼 최소 높이 48px, 초기 포커스와 Tab 유지, 확인 전 Escape/닫기 우회 차단을 적용했다.
- 제작자 테스트의 실제 스캔 버튼에도 같은 확인 흐름을 적용했다. 테스트 기록은 기존처럼 실제 수업과 분리된다.

## SQL 적용

기존 **001~012는 수정하지 않았다**. 새 테이블, 컬럼, RLS 정책, Storage 정책은 없다.

**012까지 적용된 상태에서**, Supabase SQL Editor의 새 쿼리에 013 파일 전체를 한 번 실행한다. 이미 적용한 001~012를 다시 실행하지 않는다. 코드 배포 전에 적용한다.

기존 응답에는 N_OF_M 목표 수, UNIQUE_MEMBER의 활성 팀원 수가 없고 최종 스캔 직후에는 현재 블록 QR 목록도 사라진다. 클라이언트 추측을 피하기 위해 private `scan_current_qr`를 얇게 감싸 기존 판정을 실행한 뒤 `qrScan: {mode, found, required, done}`만 추가한다. 기존 public `escape_answer_qr`, `escape_scan_qr` 모두 이를 재사용한다. UNIQUE_MEMBER의 found는 현재 활성 팀원 중 실제 기여한 사람 수이며, 같은 사람이 추가로 스캔해도 다른 팀원의 몫으로 세지 않는다. 개인정보, 정답, QR token, 원본 mission 데이터는 새 응답에 포함하지 않는다.

기존 함수는 `scan_current_qr_v9`로 보존한다. 두 private 함수의 public/anon/authenticated 직접 실행 권한은 차단한다. 기존 서버 검증과 세션 잠금 아래에서 응답을 계산하며, 저장이나 완료를 확인 버튼까지 지연하지 않는다.

## 검증 결과

- `node --test`: **99/99 통과**.
- SQL 스크립트 **10종 통과**. PGlite 로컬 PostgreSQL 환경에서 검증했다. 플레이/교사제어/결과/제작흐름/UX/Storage/교사도구 7종은 013까지 적용하고 실행했다. 기존 대기실/QR/QR문제 3종도 원래 migration 범위로 통과했다.
- 013: ANY·ALL·N_OF_M·UNIQUE_MEMBER의 정확한 개수, 같은 팀원 중복 기여 미가산, 마지막 문제 완료 후 receipt 보존, 직접 링크 RPC, 다른 팀과의 진행 분리, 중복/잘못된 QR·일시정지 차단, private 권한 차단 통과.
- 신규 headless Edge 화면 테스트: 실제 다운로드한 PNG/SVG를 jsQR로 재해독하여 동일 payload 확인, PNG 해상도/흑백/불투명/quiet zone 확인, 저장에 의한 token 변경 없음, 고1~고3 저장·필터·배지, 성공 전환 대기·재접속·부분 완료·중복 안내·서버 실패 문구·교사 일시정지 우선 반영·포커스 통과.
- 카메라 테스트는 canvas 영상 스트림을 실제 스캐너와 jsQR로 해독했다. 모달 표시 중 및 확인 직후 동일 영상에서 RPC 추가 호출이 없음을 확인했다. 실제 하드웨어 카메라는 사용하지 않았다.
- 기존 headless UI 회귀 통과: QR SVG 인쇄와 재해독, Storage 업로드, 스테이지, 몰입형 화면, 분류, 보관함 독립 QR 복사, 스토리 TXT 내보내기, 인증 콜백. 처리되지 않은 JavaScript 오류 없음.
- 빌드, JavaScript 구문 검사, diff 공백 검사 통과. 실제 Supabase 계정·수업·Storage에 테스트 데이터를 만들지 않았다.
