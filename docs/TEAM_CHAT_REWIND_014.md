# 팀 QR·블록 채팅·진행 되감기 변경 기록

2026-09-27. 구현과 로컬 검증 완료. 실제 Supabase 적용 및 GitHub Pages 배포는 아직 수행하지 않았다.

## 구현한 기능

1. **UNIQUE_MEMBER + 팀 전체**: 서버에서 1인 1QR과 팀 내 QR 선점을 강제한다. 4인 팀은 활성 QR 6개 중 서로 다른 4개만 찾아도 완료된다. 다른 팀의 같은 QR 사용은 독립적이다. ANY/ALL/N_OF_M에는 1인 제한을 적용하지 않는다.
2. 학생이 자기 QR을 찾으면 성공 확인창에 본인 완료와 `현재 팀 진행: N / M명`을 표시한다. 확인 후 추가 스캔 버튼 없이 대기하며, 팀 완료 시 기존 Realtime 진행 경로로 다음 콘텐츠로 이동한다. 새로고침에도 서버의 본인 기여 여부를 사용한다.
3. `left_at is null`인 현재 팀원을 기준으로 계산한다. QR 부족은 서버가 시작을 거부하며, 진행 중 팀 변경으로 부족해진 경우 QR 진행 영역에 경고한다. 명시적인 **수업 나가기**만 활성 인원을 줄인다. 연결 끊김/새로고침/heartbeat는 인원 변경이 아니다. 일시정지 중 및 이미 결과가 확정된 참가자의 나가기는 차단한다.
4. 각 QR에 실제 이미지와 동일한 전체 URL을 읽기 전용으로 표시하고 복사한다. 기존 token을 사용한다. PNG/SVG 저장과 A4 SVG 인쇄는 유지한다.
5. 실제 방탈출 카드끼리는 `createdAt DESC`, 동률은 ID로 정렬한다. `updatedAt`은 정렬에 사용하지 않는다. 검색·분류 필터와 새 콘텐츠 만들기 카드 위치 규칙을 유지한다.
6. 블록별 팀 채팅은 기본 OFF다. 제작기에서 새 채팅방을 만들거나 기존 방들을 연결한다. 한 블록에 여러 방을 연결할 수 있고, 참여 범위는 팀 전체 또는 역할 목록이다. 같은 방을 이후 블록에 다시 연결하면 대화를 이어 쓴다.
7. 학생은 허용된 방만 본다. 한 방이면 바로 열고 여러 방이면 목록을 표시한다. 텍스트 메시지, 역할 우선 이름, 내 메시지 구분, 스크롤/이전 메시지, 닫기, 브라우저 기준 unread를 제공한다. 현재 블록에서 채팅이 비활성화되면 아이콘을 숨기되 메시지는 유지한다.
8. 채팅은 Supabase RPC와 Realtime을 사용한다. 공개 채널에는 빈 변경 신호만 보내고, 메시지는 매번 권한을 검사하는 RPC로 읽는다. 다른 팀/역할/블록의 방 ID로 읽거나 보낼 수 없다. 작성자 정보는 recovery token으로 서버가 결정한다. 빈 문자열·공백만 있는 메시지와 1,000자 초과 입력은 거부한다. 같은 전송 request ID는 한 번만 저장하며, 참가자당 5초 내 10개 제한이 있다.
9. 수업 종료 시 채팅방/메시지를 서버에서 삭제한다. 초기화·세션 삭제 시에도 FK cascade로 삭제한다. 결과를 보관해도 채팅 내용은 보관하지 않는다. 단순 연결 끊김은 삭제 조건이 아니다.
10. 교사가 이전 순서의 블록/스테이지로 이동하면 대상부터 뒤쪽 완료·skip·강제 해제·QR 진행을 되감는다. 이전 블록 완료는 유지하고 앞으로 이동할 때는 기록을 지우지 않는다. 기존 관리 권한·revision·재시도 request ID 검증을 재사용한다.

## 되감기 범위와 기록

- 개인전: 해당 학생의 대상 블록 이후 진행만 다시 시작한다.
- 팀 전체 이동: 대상 팀 전체의 해당 범위 진행과 QR 기여를 다시 시작한다. 다른 팀에는 영향이 없다.
- 팀전에서 **학생만 이동**: 다른 학생의 일반 문제 완료는 유지한다. 단, 대상 이후의 **팀 전체 범위 QR은 팀 공유 상태이므로 팀원 전체의 해당 QR 기여를 함께 초기화**한다. 이 경우 다른 팀원도 해당 QR을 다시 수행하게 될 수 있다. 교사 관리 화면에 이 영향을 명시했다.
- 기존 이벤트/QR 기록은 `retired_at`으로 과거 이력과 현재 판정을 구분한다. 현재 고유 제약에서도 제외하므로 같은 QR을 다시 사용할 수 있다. 과거 오답 횟수·힌트 사용·교사 조작 이력은 유지한다. 현재 재풀이에 맞지 않는 해결 시간은 정확한 평균으로 재사용하지 않는다.
- 재풀이 블록과 대상 참가자를 교사 관리 기록의 `details.rewound`에 남긴다. 기존 보관 결과는 변경하지 않는다.
- 013까지 허용되던 UNIQUE_MEMBER의 한 사람 추가 기여는 014 적용 시 첫 기여를 남기고 나머지를 과거 이력으로 전환한다. 떠난 학생/다른 팀으로 이동한 학생의 해당 팀 UNIQUE_MEMBER 기여도 과거 이력으로 처리한다. QR token이나 콘텐츠를 새로 생성하지 않는다.

## 데이터와 보안

- 콘텐츠 문서 `chatRooms[]`: `{id, name, scope: 'team' | 'roles', roles[]}`. 수업용 템플릿이며 메시지를 담지 않는다.
- 블록 `chatEnabled`, `chatRoomIds[]`: 기본 OFF, 여러 방 연결. 학생용 블록 응답에는 안전한 `chatEnabled` 여부만 추가한다. 참여 역할/방 목록은 서버가 필터한다.
- `public.escape_chat_rooms`: 실제 방은 `(session_id, team_number, source_id)`로 분리한다. 수업마다 새 인스턴스와 topic을 발급한다.
- `public.escape_chat_messages`: 방, 실제 참가자, request ID, 서버가 정한 표시 이름, 텍스트, 생성 시각. RLS 활성화 및 API 역할의 직접 테이블 권한 차단.
- `escape_private.block_replays`: 참가자/블록별 재풀이 경계와 범위. 학생이 직접 접근할 수 없다.
- `escape_events.retired_at`, `escape_qr_scans.retired_at`: 현재 이벤트와 과거 이벤트를 구분한다. 활성 행만 고유 제약을 적용한다.
- 신규 공개 RPC `escape_chat`: 기존 익명 참가 token 방식으로 인증하고 현재 세션·팀·블록·역할을 검증한다. 채팅방을 열 수 있는 블록에서만 과거 대화 조회도 허용한다. 일시정지 중에는 전송할 수 없다.
- 기존 QR/teacher control/student lobby/public block 함수는 014에서 확장한다. `001~013` 파일은 수정하지 않는다. 관리자 비밀키를 사용하거나 클라이언트에 추가하지 않는다. Storage 정책은 바꾸지 않는다.
- 역할 목록은 기존 `teamSettings.roles`를 재사용한다. A/B/C/D 목록은 팀원 순서에 맞춰 배정하고, 인원이 목록보다 많으면 마지막 역할을 반복한다. 기존 조장/조원 2개 구성의 동작은 유지한다. 기존 실행 중인 학생의 역할을 migration이 일괄 재배정하지 않는다.
- 콘텐츠 복사 및 블록 보관함 가져오기에서도 채팅 템플릿 ID를 새로 만들고 블록 참조를 연결한다. 가져온 역할 설정은 대상 콘텐츠의 역할 목록에 맞춰 확인해야 한다.

## 배포 후 확인할 항목과 영향

- 실제 4개 학생 브라우저에서 UNIQUE_MEMBER 1인 1QR, 대기 인원 증가, 전체 완료 이동을 확인한다. 정상 이탈과 새로고침을 구분해 확인한다.
- A/B/C/D 역할을 설정한 새 팀전 수업에서 같은 블록의 역할별 방, 팀 전체 방, 다른 팀 격리, 이후 블록 이어쓰기를 확인한다.
- 실제 Supabase Realtime 연결의 unread/메시지 수신, 모바일 키보드와 스크롤, QR 카메라와 채팅의 번갈아 열기를 확인한다.
- 교사 뒤로 이동은 이번 단계에서 의도적으로 동작이 달라졌다. 특히 학생만 이동할 때 팀 공유 QR 초기화 안내를 확인하고 테스트 수업에서 먼저 수행한다. 앞으로 이동/조건 분기/역할 배정도 콘텐츠에 맞게 확인한다.
- 수업 종료/보관 후 초기화/삭제 후 초기화 후 이전 room ID로 접근할 수 없고 새 반에는 빈 대화가 나오는지 확인한다.
- 로컬 검증은 실제 Supabase 배포와 실기기 카메라 검증을 대신하지 않는다. 운영 적용은 위 014 실행 후 진행해야 한다.
