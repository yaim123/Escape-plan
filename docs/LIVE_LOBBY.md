# 학생 입장 및 실시간 대기실

## 설치와 사용

1. 기존 `001_foundation.sql` 적용 프로젝트에 `supabase/002_live_lobby.sql` 전체를 한 번 실행합니다. 기존 001은 다시 실행하지 않습니다. SQL은 단일 트랜잭션이므로 오류가 나면 전체가 롤백됩니다.
2. 교사 로그인 → 내 방탈출 → 콘텐츠의 **대기실** → **대기실 열기 / 돌아가기**를 누릅니다.
3. 학생에게 방 코드나 화면의 학생 입장 링크를 전달합니다. `#/join/123456`, `#/join?code=123456`, `?code=123456` 형식을 지원합니다. QR 생성 및 QR 게임 이벤트는 이번 범위에 포함하지 않습니다.
4. 학생은 학년·반·번호·이름을 입력합니다. 개인전은 바로 대기실, 팀전은 조 선택과 전체 편성으로 이어집니다.
5. 교사는 참가자와 팀을 확인하고 **게임 시작**을 누릅니다. 002 단계에서는 시작 안내를 표시합니다. 후속 003을 적용한 현재 버전에서는 첫 공개 콘텐츠와 교사 진행 화면으로 전환합니다. 상세 내용은 LIVE_PLAY.md를 참고하세요.

GitHub Pages 하위 경로에서도 상대경로 파일과 해시 라우팅을 사용합니다. 현재 로컬 주소는 이 PC에서만 접근할 수 있습니다. 학생의 다른 기기에서 사용하려면 GitHub Pages 등 실제 배포 주소가 필요합니다.

## 데이터와 권한

- `escape_contents`: 기존 소유자 RLS 유지. 학생에게 직접 접근 권한 없음.
- `escape_sessions`: 상태를 `lobby / playing / paused / finished`로 정규화하고, 세션별 난수 Realtime 채널명을 추가합니다. 활성 세션은 콘텐츠당 하나입니다. 콘텐츠 스냅샷과 정답은 서버에만 보관합니다.
- `escape_participants`: 학년·반·번호·이름, SHA-256 복구 토큰 해시, 최근 접속 시간, 퇴장 시간을 추가합니다. 기존 고유 참가자 UUID를 사용합니다. 복구 토큰 원문은 DB에 저장하지 않습니다.
- `escape_events`: 변경 없음. 문제 풀이·점수·힌트·순위 이벤트를 만들지 않습니다.
- `escape_private`: 명단 투영·해시·입력 검증·Realtime 트리거용 비공개 함수. API 역할의 스키마 및 함수 접근을 차단합니다.
- 공개 RPC 세 개만 제공합니다. `escape_teacher_lobby`는 authenticated와 `auth.uid()` 소유자 확인, `escape_join_lobby`와 `escape_student_lobby`는 anon과 참가 복구 토큰 검증을 사용합니다.
- 모든 SECURITY DEFINER 함수는 빈 search_path와 명시적 스키마를 사용합니다. 세션·참가자·이벤트 테이블의 직접 읽기/쓰기 차단을 유지합니다. 공개 SELECT 정책을 만들지 않습니다.

학생 응답은 제목·게임 방식·팀 설정·세션 상태·서버 시각·참가자 명단만 허용 목록으로 구성합니다. 원본 문서, 정답, 교사 ID, 복구 토큰/해시, 개별 진행 상태는 반환하지 않습니다. 학생이 입력한 신원 정보 자체를 학교 시스템과 대조하는 인증은 아닙니다.

## 복구, 정원, 연결 상태

- 브라우저가 암호학적 난수 256비트 토큰을 먼저 localStorage에 저장한 뒤 입장합니다. 서버는 참가자 UUID를 발급하고 해시만 보관합니다. 응답 유실 후에도 같은 토큰으로 재시도하여 중복 생성하지 않습니다.
- 저장소는 프로젝트와 방 코드별로 분리합니다. 같은 브라우저의 같은 방은 같은 학생으로 복구합니다. 서로 다른 학생 테스트는 별도 브라우저 프로필 또는 분리된 origin을 사용합니다.
- 학년·반·번호가 같은 별도 참가 시도는 거절하며 기존 토큰을 주지 않습니다. 다른 기기 복구 및 토큰 재발급은 미구현입니다.
- 입장·팀 이동·정보 수정·시작은 동일 세션 행을 잠근 후 처리합니다. 시작 후 신규 입장과 팀 이동/정보 수정/명시적 퇴장을 차단하고 기존 참가자의 복귀는 허용합니다.
- 팀 정원은 퇴장하지 않은 참가자 기준입니다. 잠시 연결이 끊겨도 자리를 다른 학생에게 넘기지 않습니다.
- “대기실 나가기”는 즉시 전체 명단에 반영됩니다. 탭 종료/네트워크 끊김은 75초 접속 유효기간과 25초 동기화 주기로 연결 끊김을 표시합니다. 명단과 팀은 유지합니다.
- 시작 요청 재전송으로 시작 시각이 바뀌지 않습니다. 종료된 세션은 새 입장 대상으로 검색되지 않으며, 교사는 새 대기실을 열 수 있습니다.

## Realtime

DB 트리거가 Supabase Realtime Broadcast로 빈 `changed` 알림을 발행합니다. 공개 채널이지만 난수 채널명을 사용하고 명단이나 게임 상태를 실어 보내지 않습니다. 알림 내용은 신뢰하지 않으며 수신자는 본인 권한으로 RPC를 재조회합니다. 따라서 위조 알림으로 팀이나 게임 상태가 바뀌지 않습니다. 민감한 데이터를 broadcast_changes로 송신하지 않습니다.

WebSocket 연결/참가 응답, heartbeat, 실패 시 지수 재연결, 재구독 후 재조회, 탭 복귀 시 동기화, 화면 이탈 시 정리를 구현합니다. 25초 동기화는 연결 누락 복구와 온라인 상태 확인용이며 즉시 반영은 Realtime이 담당합니다.

방 코드를 아는 사람의 입장은 허용하는 구조입니다. 대규모 공개 운영 전에는 게이트웨이 IP별 속도 제한, 교사 승인/차단, 별도 입장 비밀값을 검토해야 합니다. 현재 수업당 참가 기록은 500건으로 제한합니다.

## 검증 기록

- 실제 Supabase 두 교사 계정: A 생성 → B 조회·수정·삭제 결과 0건 → A 원본 보존 확인 → 테스트 행 삭제 확인 완료. 기존 콘텐츠 RLS 수정 불필요.
- Node 테스트 37개 통과(기존 33개 + 참가/Realtime 테스트 4개).
- `node scripts/verify-lobby-sql.mjs`: PGlite 0.5.8 PostgreSQL 엔진에서 마이그레이션과 실제 SQL 실행 검증 통과. Auth/Realtime 서비스는 이 로컬 검사에서 스텁이므로 실서버 브라우저 검증을 대체하지 않습니다.
- SQL 검사: 두 소유자 RLS, 타 교사 세션 접근 거부, 익명 테이블 및 비공개 함수 차단, 토큰 복귀/중복 신원 거부, 정원, 퇴장, 팀 이동, 정보 변경, 시작 후 잠금, 원본 정답 미포함, 빈 Broadcast payload, 데이터 정리.
- 실서버 팀전: 교사 대기실 개설, 학생 A/B 입장, 각기 다른 조 선택, 정원 마감 버튼, 이름 변경, 퇴장/재입장, 새로고침 복구, 종료 동기화 통과.
- 실서버 Realtime: B의 2조→3조 이동이 교사와 A 화면에 457ms 내 반영, 교사 시작이 A/B 화면에 313ms 내 반영. 25초 보완 동기화보다 빠른 Broadcast 수신 경로 확인.
- 실서버 API 검사: 원본 테이블 네 개의 익명 접근 차단, 잘못된 토큰/중복 신원 거부, 응답 필드 허용 목록, 동일 토큰 참가 UUID 유지 통과. 동시에 정원 1명인 조를 선택한 두 요청 중 하나만 성공.
- 실서버 시작 후: 서버 시작 시각, 기존 참가자 복구 통과. 신규 입장과 팀 변경 요청은 서버에서 거부. 학생 B 브라우저 새로고침 후에도 시작 상태 유지.
- 교사·학생 A·학생 B의 수집된 콘솔 오류/경고: 모두 없음. API 부정 요청 테스트에서 발생한 의도한 거부와 정상 화면 오류를 구분했습니다.
- 브라우저 환경 제한: 자동 제어 가능한 브라우저가 Codex 내장 브라우저뿐이어서 3개 탭을 사용했습니다. 학생 A(127.0.0.1)와 B(localhost)는 origin 및 localStorage가 분리됩니다. Chrome 호출은 사용할 수 없음으로 반환되어 다른 브라우저 제품 간 교차 검증은 미실행입니다.
- 2026-09-24 개인전 실서버 최종 확인 완료: 조 선택 없이 입장, 참가 1명 유지, 새로고침 복구, 교사 시작의 학생 즉시 반영, 교사/학생 콘솔 오류·경고 없음.
- 대기실 검사 콘텐츠 `e08fda74-58db-4d30-a3a7-7cf12ec15792`(코드 485349) 삭제 완료. Supabase 재조회 콘텐츠 목록 0건 및 기존 학생 토큰의 “참가 기록을 찾을 수 없습니다” 응답 확인. 해당 콘텐츠에 연결된 모든 세션·참가자·이벤트는 기존 ON DELETE CASCADE 외래키로 삭제됩니다. 두 교사 RLS 검사 데이터도 이미 삭제 확인 완료. 테스트용 교사 Auth 계정 자체는 사용자 계정이므로 삭제하지 않았습니다.

## 후속 범위

002 단계는 위 검증과 정리까지 완료했습니다. 후속 003의 실제 문제 플레이·최소 교사 진행도는 LIVE_PLAY.md에 별도로 기록했습니다. 전체 일시정지/재개, 일시정지 시간 제외, QR 상호작용, 실제 수업 점수·힌트·순위와 최종 결과는 후속 범위입니다.
