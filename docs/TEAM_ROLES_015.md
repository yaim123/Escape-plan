# 팀 설정·역할 경로·대기 화면 (015)

## 구현한 기능

- 개인전에서는 E. 팀 설정 전체와 블록 채팅 설정을 숨긴다. 팀전으로 돌아오면 역할/채팅/대기 설정을 복원한다.
- 팀 설정을 기본 팀 구성 → 역할 → 역할별 화면 → 팀 채팅 → 팀 대기 화면으로 구성했다.
- 역할 이름과 인원(1~20명), 추가/삭제, 총 자리를 제공한다. 같은 이름 중복 행은 거부한다. 참조 중인 역할 변경/삭제는 블록·채팅방 개수를 알리고 확인한다. 참조를 자동 변경하지 않으며 잘못된 참조는 실행 전에 거부한다.
- 역할 대상 복수 선택, 작은 배지, 목록 역할 필터(순서를 유지하며 비대상 흐리게 표시), 학생 미리보기 역할 선택을 제공한다.
- 비대상 블록은 서버의 현재/가능 콘텐츠와 필수 진행 경로에서 제외한다. 거짓 완료 이벤트를 생성하지 않는다. 직접 제출/선택/힌트 및 QR 호출, 교사 강제 해제로도 역할 접근을 우회할 수 없다.
- 팀 채팅 전역 OFF는 설정을 보존하면서 관리 UI, 블록 옵션, 학생 아이콘, 서버 채팅 RPC를 차단한다.
- 서버가 입증한 개인 기여 완료에 사용자 지정 대기 제목/안내/인원 표시를 적용한다. UNIQUE_MEMBER는 활성 기여 인원, 일반 전원 완료는 실제 완료 인원을 사용한다. 다른 완료 방식에서는 의미가 불명확한 숫자를 생략한다.

## 기존 모델 분석과 호환

- 기존 `assignment.mode`의 all/auto/member/role은 **수행 담당자**, `completion`은 **완료 판정**이다. 이 둘을 별도 진행 엔진으로 대체하지 않았다.
- 표시 범위를 `assignment.visibleRoles: string[]`로 확장했다. 빈 배열은 팀 전체이며, 새 필드가 없으면 기존 `assignment.mode='role'`의 단일 역할을 사용한다. 새로운 전역 `teamSettings.roleViewsEnabled`가 켜진 팀전에서만 적용한다. 기본은 OFF다.
- 표시 범위와 기존 담당자 제한은 함께 적용된다. 자동 배정/특정 팀원/기존 특정 역할이 따로 설정되어 있으면 그 제한도 유지한다. 충돌하여 아무도 수행하지 못하는 설정은 실제 참가자 구성으로 시작할 때 거부한다.
- `completion.assigned`는 실제로 볼 수 있고 배정된 팀원이 대상이다. `all`을 자동으로 역할 완료로 바꾸지 않는다. 일부 역할에게 숨기면서 전원 완료를 요구하거나, UNIQUE_MEMBER를 일부 역할에게만 공개하는 모순은 실행 전 안내한다.
- 조건이 없는 순차 경로만 비대상 블록을 건너뛴다. 명시적인 AND/OR/N 협동 조건은 그대로다. 다른 역할의 완료를 명시적으로 기다리도록 구성할 수 있다.
- `teamSettings.roles`는 기존 확장 배열을 그대로 유지한다. 기존 배열을 읽거나 정규화하는 것만으로 순서를 바꾸지 않는다. 역할 행을 편집할 때 인원 순서로 확장한다.
- 기존 014 채팅 문서의 호환을 위해 `teamSettings.chatEnabled`가 없으면 팀전에서 ON으로 해석한다. 개별 블록 채팅은 기존처럼 별도로 켜야 한다. 명시적 false는 모든 하위 설정보다 우선한다.
- `teamSettings.waiting`은 `{title, body, showCounts}`다. 값이 없거나 문구가 비어 있으면 기본 제목/안내를 사용한다.
- 기존 014 채팅 테이블, 메시지 이력/권한, 빈 Realtime 알림 후 재조회, QR 토큰/기여, 되감기 기록을 재사용한다. 기존 콘텐츠 문서·활성 스냅샷·보관 결과를 일괄 변환하지 않는다.

## 회귀 위험과 운영 시 주의점

- 마지막 역할 자동 반복은 의도적으로 제거했다. 기존 역할 두 자리로 네 명을 시작하던 문서는 역할 인원을 늘려야 한다. 기존 실행 중 스냅샷의 역할을 일괄 재배정하지는 않는다.
- 비대상 블록은 기본 순서에서만 생략한다. 다른 역할/팀원의 완료를 명시적으로 기다리는 조건까지 자동 해제하지 않는다.
- 개인 기여 완료가 입증되지 않으면 사용자 지정 완료 대기를 표시하지 않는다. QR ALL/N_OF_M처럼 사람별로 환산할 수 없는 조건에 인원수를 추정하지 않는다.
- 수업 중 필수 역할 학생이 나가 최종 조건을 더는 충족할 수 없으면 기존 교사 관리/팀 변경으로 조정해야 한다. 이를 탈출 성공으로 위조하지 않는다.
- 브라우저의 역할 숨김은 보안 경계가 아니다. 015 서버 적용을 마친 뒤 새 역할 화면 기능을 사용해야 한다.
