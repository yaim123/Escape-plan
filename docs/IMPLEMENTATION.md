# 구현 현황 및 다음 단계

## 개발 단계

SPEC.md §53의 단계별 개발 원칙에 따라 콘텐츠 제작에서 로컬 시험까지 연결한 첫 번째 작업 단위입니다. 로컬 체험과 Supabase 교사 계정의 온라인 콘텐츠 저장을 지원하며, 실제 프로젝트에서 기본 읽기·쓰기와 권한 검사를 완료했습니다.

| 영역 | 상태 |

## 범위와 동작 원칙

- 원본 room 객체에는 플레이 이벤트를 기록하지 않습니다. 테스트 상태는 별도 session입니다.
- 역할과 팀원 번호를 분리합니다. 역할 기능을 끄더라도 자동/특정 팀원 배정을 사용할 수 있습니다.
- 현재 자동 배정은 전체 콘텐츠 인덱스를 기준으로 라운드 로빈 처리합니다. 실제 수업 단계에서 스테이지 내 문제 묶음 단위 배정과 재분배 정책을 추가할 예정입니다.
- 완료 조건이 없는 기본 블록은 앞선 블록의 완료를 기다립니다. 명시적인 공개 조건이 있는 블록은 조건 충족 여부를 기준으로 독립적으로 공개됩니다.
- 명시적인 조건 순환은 저장 시 차단합니다. 순차 진행과 대상 배정을 섞어 생기는 논리적 교착은 아직 정적 분석하지 않으며 가상 테스트로 확인합니다.
- 순서 배열형은 순번별 선택 목록, 짝맞추기형은 왼쪽 항목별 오른쪽 항목 선택으로 구현했습니다.
- 교사 승인형은 정답 문자열로 통과할 수 없습니다. 실제 수업에서는 소유 교사의 승인 RPC가 teacher 이벤트를 기록합니다.
- 006은 실제 플레이 결과와 시간·점수 페널티, 서버 힌트 제한·공유를 구현합니다. 실제 적용 및 검증 상태는 RESULTS_AND_RESET.md를 확인합니다.
- 가상 팀 테스트와 실제 학생 수업은 별도 세션입니다. 실제 수업은 게임 시작 시 팀원 번호와 역할을 확정합니다.
- 화면의 PC/태블릿/모바일 미리보기는 해당 기기 폭으로 축소한 콘텐츠 미리보기입니다. 실제 브라우저별 렌더링/접근성 검증을 대체하지 않습니다.
- 내보낸 JSON에는 제작자 정답이 포함됩니다. 학생 배포용 데이터 형식이 아닙니다.
- 정답 문자열과 내용은 HTML로 해석하지 않고 텍스트로 표시하며 미디어는 http(s) URL만 허용합니다.

## 다음 구현 순서

1. 추가 검증: 다른 브라우저 제품/실기기, 교사 실서버 토큰 만료/갱신과 저장 실패 확인. 두 교사 RLS 및 현재 개인/팀 실제 플레이 검증은 완료.
2. 이번 범위의 서버 정답 판정, 입력 미저장, 요청 중복 방지, 대상별 콘텐츠 공개, 진행 동기화 및 최소 교사 진행도는 구현 완료. 상세한 한계와 결과는 LIVE_PLAY.md 참조.
3. 전체 일시정지/재개, 정지 시간 제외, 대상별 강제 관리는 004·005에 구현. QR 상호작용은 후속 별도 단계.
4. 006 결과·순위·보관/삭제 초기화 검증 완료. 자세한 범위와 테스트 환경은 RESULTS_AND_RESET.md 참조.
5. Storage 업로드 권한, 파일 형식/크기 검증, BGM 및 배경 설정, 태블릿 드래그 조작 보강.

보안상 학생 접근을 위한 임시 공개 SELECT 정책이나 클라이언트 정답 판정 수업 모드는 추가하지 않았습니다. 실제 수업 운영의 완료를 주장하지 않습니다.
