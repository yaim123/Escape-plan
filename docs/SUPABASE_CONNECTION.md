# Supabase 연결 및 검증

대상 프로젝트: `https://rxknixllqewkvgfnpshu.supabase.co`

## 설정 위치

`src/config.js`의 `SUPABASE_CONFIG`에 Project URL과 Publishable Key를 설정했습니다. Next.js 환경변수나 서버 런타임은 사용하지 않습니다. `src/data/config.js`는 기본 설정과 브라우저별 재정의를 검증하며, `src/data/supabase.js`는 기존 REST 기반 클라이언트입니다.

Publishable Key는 `apikey` 헤더에만 전달합니다. `Authorization: Bearer`에는 로그인 사용자의 액세스 토큰만 넣습니다. 익명 권한 검사는 로그인한 상태에서도 사용자 토큰을 제외합니다. Secret Key와 service_role JWT는 설정 저장·클라이언트 생성·정적 빌드 검증에서 거부합니다.

| 두 교사 계정 사이 조회·수정·삭제 격리 | 2026-09-23 실제 A/B 계정 검사 통과. B의 조회·수정·삭제 결과 0건, A 원본 보존 확인 후 검사 행 삭제 완료 |

익명 조회의 `permission denied for table`은 SQL의 REVOKE에 의한 테이블 권한 차단입니다. 이것만으로 교사별 행 수준 RLS가 모두 검증되었다고 판단하지 않습니다.

## 브라우저 검사 절차

1. 같은 탭에서 교사 로그인합니다. 비밀번호를 코드나 채팅에 기록하지 않습니다.
2. 저장 공간 설정 → 연결·읽기·쓰기 검사를 실행합니다.
3. 테스트 전용 콘텐츠 한 건을 생성하고, 제목·소유자·문서를 재조회합니다.
4. 제목을 변경해 원본 문서와 DB 행에 반영되는지 확인합니다.
5. 익명 쓰기와 로그인한 사용자의 소유자 위조 쓰기가 42501로 차단되는지 확인합니다.
6. 현재 앱에 열지 않은 수업 테이블의 교사 직접 접근 차단을 확인합니다.
7. 검사 전용 행만 삭제하고 재조회로 확인합니다. 정리에 실패하면 해당 테스트 ID를 화면에 표시합니다.

권한 차단 검사는 의도적으로 HTTP 401/403 응답을 발생시킵니다. 브라우저 콘솔의 해당 네트워크 메시지와 예상하지 못한 JavaScript 오류·CORS 오류는 구분해야 합니다.

## 변경 범위

- 정적 공개 설정, 프로젝트별 세션 분리, 브라우저 fetch 호출 컨텍스트 수정
- 20초 요청 제한, HTTP 상태/DB 오류 코드 보존, 동시 토큰 갱신 중복 방지
- 기존 빌드에서 공개키 검증 및 정적 설정 포함
- 읽기·쓰기 및 권한 검사 화면, 공개 연결 확인 CLI
- SQL 정책 수정 없음, 학생 실시간 접속/교사 대시보드 구현 없음

## 로그인 문제 보완

- 브라우저의 fetch가 저장소 객체를 수신자로 호출되던 방식을 전역 컨텍스트에 바인딩했습니다.
- 로그인 화면의 임의 8자 최소 길이 제한을 제거했습니다. 기존 계정의 비밀번호는 서버에서 확인하고, 신규 비밀번호 기준도 서버 오류로 안내합니다.
- GoTrue 응답의 숫자 `code`보다 문자열 `error_code`를 우선하여 인증 실패 원인을 정확하게 분류합니다.
- 잘못된 계정, 이메일 미인증, 발송 한도, 발송 대상 제한을 한국어로 안내합니다.
- Supabase 관리 사이트 로그인과 이 앱의 교사 계정이 별개임을 화면에 표시합니다.
- 인증 화면을 열어둔 상태에서 코드가 수정되면 새로고침해야 새 버전이 적용됩니다.
