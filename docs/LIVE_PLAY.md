# 실제 문제 플레이와 진행 동기화

## 적용 및 사용

기존 001·002 이후 `supabase/003_live_play.sql`을 한 번 적용합니다. 현재 연결된 프로젝트에는 사용자가 적용을 완료했고 실제 RPC로 동작을 확인했습니다. 기존 SQL 재실행이나 추가 SQL 실행은 필요하지 않습니다. 적용 전에 시작한 수업은 종료하고 새 대기실을 열어야 합니다.

교사는 콘텐츠의 대기실에서 학생 입장 후 게임을 시작합니다. 학생에게 첫 공개 콘텐츠가 표시되고 교사에게 참가자별 현재 콘텐츠·완료 수·오답 수와 팀별 진행도가 표시됩니다. 모든 콘텐츠 완료 후에는 대기 안내만 표시합니다. 최종 결과·순위·점수·힌트·QR 이벤트·전체 일시정지 기능은 이번 범위 밖입니다.

## 데이터와 보안

| 대상 | 변경 |
| --- | --- |
| `escape_sessions` | `play_version`, `progress_revision` 추가. 시작 트리거가 팀원 번호·역할과 초기 진행을 확정 |
| `escape_participants.progress` | 기존 JSON에 현재 위치, 개인/팀 완료 목록, 공개 목록, 오답 횟수 저장 |
| `escape_block_progress` | 신규. 참가자·블록별 오답 횟수와 완료 시각 |
| `escape_submission_receipts` | 신규. 요청 UUID·블록·판정 결과만 저장해 재전송 중복 처리 방지 |
| `escape_events` | 완료·버튼·승인 이벤트 기록 및 중복 방지 인덱스 |
| `escape_private` | 배정·완료·조건 평가, 정답 판정, 학생용 응답 생성 비공개 함수 |
| `escape_student_play` | 참가 토큰으로 본인에게 공개된 콘텐츠 조회·선택·제출 |
| `escape_teacher_progress` | 로그인한 수업 소유자의 진행 조회 및 승인형 문제 승인 |

새 테이블은 RLS를 활성화하고 anon/authenticated 직접 접근을 차단합니다. 기존 콘텐츠 소유자 RLS는 유지하며 공개 SELECT 정책은 추가하지 않았습니다. 서버 함수는 SECURITY DEFINER, 빈 search_path 및 명시적 스키마를 사용합니다. 학생은 Supabase Auth 계정 없이 기존 복구 토큰으로 본인 참가 기록에만 접근합니다.

정답은 보호된 수업 스냅샷에 남습니다. 학생 응답에는 현재 문제 표시용 필드와 본인에게 공개된 제목 목록만 포함하며 정답 배열·정규화 설정·힌트·원본 문서·다른 팀의 진행을 반환하지 않습니다. 짝맞추기는 대응 순서를 제거한 정렬된 후보 목록만 반환합니다. 학생 경로에서는 교사용 예제와 로컬 정답 판정 모듈도 불러오지 않습니다. 교사 미리보기/JSON 백업은 정답을 포함하므로 학생 배포 용도가 아닙니다.

학생 제출 문자열은 판정 요청과 메모리 내 재시도에만 사용하며 DB, localStorage, 앱 로그에 저장하지 않습니다. DB에는 오답 횟수와 요청 판정 결과만 저장합니다. 플랫폼 인프라 로그 설정 자체를 감사한 것은 아닙니다. 요청당 입력 크기와 참가자당 분당 제출 횟수도 제한합니다. Secret/service_role 키를 사용하지 않습니다.

## 기존 명세 유지

- 개인전은 해당 참가자 이벤트만, 팀전은 같은 팀의 이벤트만 평가합니다.
- 전체/자동/팀원 번호/역할 배정, 누구나/모두/N명/팀원/역할/배정 대상 완료 판정을 유지합니다.
- AND/OR/N개 조건과 이벤트·팀원·역할 필터를 서버에서 다시 평가합니다. 명시 조건이 없으면 이전 블록 완료를 기다리고, 명시 조건이 있으면 독립적으로 해제합니다.
- 자동 배정은 기존 JS 엔진과 같은 전체 콘텐츠 인덱스 기준입니다. 스테이지 단위 재배분은 새로 구현하지 않았습니다.
- 교사 승인형은 학생 입력으로 통과할 수 없습니다. 소유 교사만 공개된 승인형 문제를 승인할 수 있으며 source=teacher 이벤트를 남깁니다.
- 완료 후 팀 전체 진행을 갱신합니다. 현재 선택한 콘텐츠가 유효하면 유지하고, 완료되면 다음 공개 콘텐츠로 이동합니다.
- Realtime은 빈 변경 신호만 전달하고 수신자가 권한을 검사하는 RPC로 다시 조회합니다. 응답 revision으로 과거 응답의 덮어쓰기를 막습니다. 25초 보완 동기화 및 재접속 복구도 유지합니다.
- 팀원의 완료로 다음 문제로 이동하면 이전 오답 안내를 지웁니다. 같은 문제의 단순 동기화에서는 작성 중인 답안을 유지합니다.

## 실제 검증 결과 (2026-09-24)

이전 대기실 단계의 개인전 최종 검증과 데이터 정리를 먼저 완료했습니다. 기록은 LIVE_LOBBY.md에 있습니다.

| 검사 | 실제 결과 |
| --- | --- |
| 개인전 | 스토리→단답→객관식→암호, 완료 4/4 |
| 오답·복구 | 오답 1회 저장, 새로고침 후 같은 문제와 횟수 복구, 입력란은 비어 있음 |
| 교사 개인 진행 | 현재 콘텐츠 완료 4/4·오답 1회 표시 |
| 팀전 시작 | 교사 시작 후 두 학생의 첫 스토리 표시 757ms |
| 팀 진행 공유 | A 스토리 완료가 B에 402ms, A 정답 완료가 B의 다음 문제에 406ms 내 반영 |
| 다른 팀 격리 | API 참가자가 2조를 4/4 완료해도 1조는 1/4 유지 |
| 팀 재접속 | 두 탭 새로고침 후 동일 위치 복구, 3/4에서 재복구 확인 |
| 팀 최종 진행 | B의 마지막 정답이 A와 교사에 반영. 두 학생 모두 4/4, 개인 오답 A=0/B=2 |
| 실서버 API | 6개 테이블 익명 접근 거부, 잘못된 토큰 거부, 학생 응답 필드 허용 목록 및 비공개 단답 정답 미포함 |
| 중복 제출 | 같은 요청 UUID로 오답을 재전송해도 횟수 1회 유지 |
| 콘솔 | 교사·학생 A·학생 B 정상 플레이 중 오류/경고 모두 0건 |
| 자동 검증 | Node 39개 통과. PGlite SQL 검사 통과: 11문제 유형, JS 엔진과 배정/완료/조건 일치, 승인 권한, 입력 미저장, RLS, 연쇄 삭제 |

실제 브라우저 검증은 Codex 내장 브라우저 3개 탭으로 수행했습니다. 학생 A는 127.0.0.1, B는 localhost로 origin과 저장 공간을 분리했습니다. Chrome/Edge 등 서로 다른 브라우저 제품 간 검증은 미실행입니다. SQL 엔진 검사는 Auth/Realtime 스텁을 사용하므로 실서버 검사와 구분합니다.

## 테스트 데이터 정리

실제 플레이 검증 콘텐츠 `a96249a8-fa6d-4b7f-9365-2c1ec9feffc0` (코드 184435)를 소유 교사로 삭제했습니다. 교사 화면 새로고침 후 Supabase 콘텐츠 목록 0건을 확인했고, 학생 A/B 및 별도 API 참가자 모두 기존 토큰으로 조회하면 `참가 기록을 찾을 수 없습니다.`가 반환됐습니다.

콘텐츠→세션→참가자·이벤트→블록 진행·제출 기록은 모두 ON DELETE CASCADE 외래키로 연결되어 삭제됩니다. 새 테이블의 연쇄 삭제는 SQL 엔진 검사에서도 확인했습니다. DB 관리자 접속으로 각 테이블의 전역 COUNT를 직접 조회한 것은 아니며, 위 소유자 조회·기존 토큰 거부·외래키 제약을 근거로 해당 테스트 데이터 정리를 확인했습니다. 이전 RLS/대기실 검사 콘텐츠도 삭제 완료입니다. 교사 Auth 계정은 유지했습니다.

## 변경 파일 및 재검사

- `supabase/003_live_play.sql`: 새 마이그레이션. 001·002 수정 없음.
- `src/data/play.js`: 학생/교사 RPC 및 제출 재시도 ID.
- `src/ui/live-play.js`: 실제 플레이어와 최소 교사 진행 대시보드.
- `src/ui/lobby.js`, `src/app.js`, `src/lobby.css`: 시작 전환·교사 모듈 지연 로딩·스타일.
- `src/ui/settings.js`: 현재 제공 범위 안내.
- `tests/live-play.test.js`, `scripts/verify-play-sql.mjs`: 클라이언트와 서버 SQL 검사.
- `scripts/verify-live-play.mjs`: 폐기용 4블록 콘텐츠의 실서버 검사. 로컬 예제의 단답 정답을 `청록열쇠-729`로 변경한 후, 2조와 학생 번호 12-99-990을 예약해 사용합니다. 수업 시작·종료·콘텐츠 삭제는 교사 화면에서 수행합니다. 실제 학생 수업에서는 실행하지 않습니다.
- `scripts/generate-play-normalization.mjs`: SQL Unicode 정규화 생성 도구. 이미 적용한 마이그레이션을 변경하기 위해 재실행하지 않습니다.
- README 및 구현 현황 문서 갱신. SPEC.md 원문 유지.

`node --test`, `node scripts/build.mjs`로 기본 검증합니다. PGlite가 준비된 개발 환경에서는 `node scripts/verify-play-sql.mjs`로 SQL을 검사합니다. 런타임 의존성·GitHub Pages 빌드 구조는 유지하며 SQL/검증 도구는 배포 파일에 포함되지 않습니다.
